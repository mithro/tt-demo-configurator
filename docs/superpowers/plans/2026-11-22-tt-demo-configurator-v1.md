# Tiny Tapeout demo configurator v1: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A static web app on GitHub Pages that builds, previews, tests and installs `/demo.json` demo sequences
on Tiny Tapeout RP2350 dev boards, on both stock and demo-mode firmware.

**Architecture:** SolidJS + SUID + Vite single-page app. Pure, unit-tested modules (format validator, raw-REPL
protocol, board scripts, ini editing, hand-made import) under `src/lib/`; thin UI components under `src/ui/`.
The board is driven over WebSerial with MicroPython's raw REPL (Ctrl-A, code, Ctrl-D; reply `OK<out>\x04<err>\x04>`).
Bundled data (ready-made sequences, pinned firmware `demo.py`, stock `main.py` files, a trimmed VGA-videos index)
lives in `src/data/` and is regenerated by scripts in `scripts/`.

**Tech Stack:** TypeScript, SolidJS 1.9, @suid/material, Vite 5, Vitest 2, GitHub Actions `actions/deploy-pages`.

**Spec:** `docs/superpowers/specs/2026-11-20-tt-demo-configurator-design.md`

## Global Constraints

- Format: `{"version":1,"shuttle":<str>,"projects":[{address,subtile,duration_ms,clock_hz,ui_in,steps}]}`; all
  fields required, unknown fields are errors, steps are exactly `{"set":0..255}` or `{"wait_ms":>=0}`, non-empty
  steps must wait > 0 in total, `projects` non-empty. Error strings match firmware `demo.py` word for word.
- Firmware `demo.py` pinned from `mithro/tt-micropython-firmware` branch `demo-shuttle-sequences` @ `1c93680`.
- RP2350 only; RP2040 boards and FPGA boards are detected and refused (FPGA: "detect only").
- Stock helper files: `/demo.py` (pinned copy), `/main.py` wrapper, `/main_stock.py` (the original `main.py`).
- No flashing from the browser: link to `.uf2`, plus `machine.bootloader()`.
- Theme `#544ead` / `#8afbfd`; Apache-2.0; deploy from `main` with GitHub Pages; vite `base: './'`.

## Review Focus

1. Writing a file larger than one REPL chunk (demo.py is ~25 KB) must arrive byte-identical → test chunked
   write round-trips through the fake REPL.
2. A board whose `main.py` is neither stock nor our wrapper (user-edited) → detected as `stock` with
   `mainIsStock=false`; install warns, never overwrites without keeping `main_stock.py`.
3. config.ini with `demo = yes` under a project section, or `[DEFAULT]` missing → `setDemoLine` only edits
   `[DEFAULT]`, creating it at the top if absent.
4. JSON with booleans as ints (`"ui_in": true`) → invalid (bool is not int), as on the board.
5. Board with 0 projects loaded for its shuttle → make-permanent refused with the upgrade message.

### Task 2: Format types and validator — `src/lib/demoFile.ts`
Produces: `type Step = {set:number}|{wait_ms:number}`, `interface Entry {address,subtile,duration_ms,clock_hz,ui_in:number; steps:Step[]}`,
`interface DemoFile {version:1; shuttle:string; projects:Entry[]}`,
`validateDemo(conf: unknown, shuttle: string, lookup?: (key: number|string) => {name:string, danger_level?:string|number}|null): string[]`,
`entryKey(e: Entry): number|string`, `parseDemoText(text, shuttle, lookup?) -> {file?: DemoFile, errors: string[]}`,
`formatDemo(file): string` (stable key order, one project per line).
- [ ] Tests in `src/lib/demoFile.test.ts` with fixtures `test/fixtures/{good,bad}/*.json`; each bad fixture's expected
  error list is in `test/fixtures/bad/<name>.errors.txt` copied from the firmware's messages.
- [ ] `test/check_fixtures_on_firmware.py` runs the same fixtures through the pinned `demo.py` `validate()` on the
  desktop (PYTHONPATH firmware `src`) and asserts identical error lists. Commit.

### Task 3: Raw REPL over a byte transport — `src/lib/rawRepl.ts`
Produces: `interface Transport {write(b: Uint8Array): Promise<void>; read(): Promise<Uint8Array|null>}`,
`class RawRepl {constructor(t: Transport); enter(): Promise<void>; exec(code: string, timeoutMs?): Promise<{out:string, err:string}>; run(code): Promise<string> /* throws ReplError on err */; exit(): Promise<void>}`,
`class SerialTransport implements Transport` (WebSerial).
- [ ] Tests with a scripted fake transport: banner, normal exec, error exec, output split across reads, timeout. Commit.

### Task 4: Board file and detection scripts — `src/lib/board.ts`
Consumes RawRepl. Produces: `readFile(r, path): Promise<string|null>`, `writeFile(r, path, text)` (base64 chunks of
1024 bytes into a temp file then `os.rename`), `removeFile`, and `detect(r): Promise<BoardInfo>` where
`BoardInfo = {sdk:string|null, rp2350:boolean, shuttle:string|null, romCommit:string|null, romRepo:string|null, isFpga:boolean,
projects:number, firmware:'custom'|'helper'|'stock'|'handmade', demoSetting:boolean, demoJson:string|null,
demoErrors:string[], mainText:string|null, configIni:string|null, vgaCycle:string|null}` parsed from one JSON line
printed by `src/lib/py/detect.py`.
- [ ] Tests: `parseDetect` on recorded outputs for each firmware type; writeFile round-trip through a fake REPL that
  executes the base64 protocol. Commit.

### Task 5: Helper install, ini editing, stock check — `src/lib/helper.ts`
Produces: `WRAPPER_MAIN` (text), `setDemoLine(ini: string, value: 'yes'|'no'|null): string`,
`isStockMain(text: string, sdk: string): boolean` against `src/data/stock-main/<version>.py`,
`installHelperOps(info)`, `removeHelperOps(info)` → `FileOp[]` = `{op:'write'|'remove'|'rename', path, text?, to?}`.
- [ ] Tests for each Review-Focus ini case and op lists for stock/helper/handmade states. Commit.

### Task 6: Run from RAM, validate on board — `src/lib/live.ts`
Produces: `boardValidate(r, file): Promise<string[]>`, `testFromRam(r, file)`, `showOne(r, entry)`, `playOne(r, entry)`,
`stopRam(r)`. Uploads `demo.py` source into a RAM module (`exec` into a fresh module dict) when the firmware lacks
`ttboard.demo`, then `DemoRunner(tt, entries, path='(web)')`.
- [ ] Tests: generated Python compiles with `mpy-cross` (vitest calls a Python checker script) and contains the JSON. Commit.
